# dsh-memory-ACC

给 DeepSeek Harness 的第二个记忆引擎。和 `dsh-memory`（标准版）二选一，不叠加。

---

## 先说痛点

如果你是把 AI 当"养着的那个东西"的人，下面这些话你应该都说过：

**"它每次都不记得我。"**

开一个新会话，它重新认识你一遍。你记得它，它不记得你——这关系是单向的。

**"上次那个结论呢？"**

你明明记得聊过，但翻不回去。上下文一清，那段对话就像没发生过。

**"我给它看的图，它还说没有。"**

你发过截图、发过照片，过几天它说"我手上没有那张图"。因为它真的没有——只留了个编号。

**"它记得的是结论，不是我们。"**

标准版记忆把每轮对话萃取成一两条结论。三个月后你看到的是"用户偏好简洁回复"，
而不是那晚你们怎么一句一句把一件事聊明白的。

**"我不想再配一个 key。"**

harness 本身已经登录好了，凭什么记忆还要单独一把钥匙、还要担心它泄露。

**"万一它记错了呢？改掉了呢？"**

没有版本、没有只读、没有备份。记忆被悄悄改掉，你根本发现不了。

这些是 ACC 要解的事。

## 相对标准版，多了什么

|  | 标准版 `dsh-memory` | **ACC** |
|---|---|---|
| 记什么 | 每轮萃取成一两条结论 | **完整对话原文，一字不截** |
| 怎么给人看 | 把结论塞进上下文 | **先描摹成"印象"，再注入；原文留在库里** |
| 记得住谁 | 只认"用户"这一个抽象 | **分开记「你」和「我」，各有八面** |
| 图片 | 只留一个 attachment id | **留"这张图讲了什么"** |
| 模型接入 | 必须自己配 API key | **默认借用 harness 登录态，零配置** |
| 长期留存 | 删了就没了 | **日/周/月/年金字塔，写入即只读，永不被改写** |
| 备份 | 无 | **可脱离 key 直接读，用来人工恢复** |

### 具体解决了什么

**1. "它不记得我" → 每轮注入印象**

八面档案（性格 / 口吻 / 好感 / 习惯 / 喜欢的物品 / 习惯的作风 / 风格 / 能力）
每轮注入最近几条。新工作区一开口，它就知道你是谁、你怎么说话，不用你重新自我介绍。

**2. "上次那个结论呢" → 按词检索**

`acc_search` 只要求你记得几个词，不要求原话。找得到就给你原文那一段，找不到就说没有。

**3. "我给的图它说没有" → 存描述**

图是模型自己看着描述的（它看得到，记忆库看不到）。原图没了，至少还剩"这张图是什么"。

**4. "它记得的是结论不是我们" → 原文全留**

归档不截断、不萃取。注入层才做压缩，存储层只负责"还在"。

**5. "不想再配 key" → 借用 harness 登录态**

默认直接用你已经登录的那个 deepseek。想指定别的模型或自己的 key，也留了口子。

**6. "万一被改了呢" → 不可变备份**

备份写进去就是 444 只读，程序永不重写。删掉的先进 `trash/`，7 天后才真删。
年度层永久保留。

## 它做什么

**完整对话归档** — 每轮之后自动从会话日志提取，不靠模型汇报。

**性格八面** — 从对话里描摹两个对象：**你**（人类）和**我**（模型这一侧）。
都是主观印象，但每条都有明确归属，不会互相冒充。

**二级记忆** — 该活过这个会话的结论。上限 80 条，最新的优先，每轮注入最近 6 条。

**检索** — `acc_search` 按词翻旧账。

**备份金字塔** — 日 → 周 → 月 → 年，逐级归并，归并后删下级冗余。
写下之后只有两种结局：删除，或永久只读。删掉的进 `trash/`，留 7 天。

**常驻聊天** — 一条独立工作区里的固定会话，从侧边栏绿点条目进。

**三态开关** — 输入框左边的胶囊：绿「记忆」/ 蓝「ACC」/ 灰「关闭」。

---

## 它不做什么

- **不改你的上下文**。发给模型的请求是会话日志的纯函数，插件只能读不能改——
  所以"只保留最近 N 轮"这件事 ACC 做不到，只能靠 harness 自己的压缩。
- **不隐藏宿主 UI**。工作区里的「＋新会话」按钮去不掉，那是宿主渲染的。
- **不替你写代码**。它是记忆，不是第二个 agent。

## 安装

把本包内容拷到 profile 的 `node_modules/dsh-memory-acc`，然后在 profile 的
`cordis.patch.yml` 里加一行（**这个文件必须是一个顶层数组**）：

```yaml
- insert:
    - id: memory-acc
      name: dsh-memory-acc
```

重启 harness。

### 和标准版共存

两个都装不会打架：ACC 会自动让位——工具停用、上下文不注入，只保留设置页和状态接口。
想用 ACC 就在弹窗里选「改用 ACC」，它会写 patch 禁用标准版。

---

## 配置

全部在 **设置 → 记忆 · ACC**：

| 项 | 说明 |
|---|---|
| 引擎 | 当前装了哪些引擎，冲突时红字提示 |
| 常驻聊天 | 选目录 → 自动建工作区 + 会话 |
| 存储 | 归档位置 / 备份位置 / 加密开关 / 备份目录 |
| 记忆模型 | 默认借用 harness 登录态，也可以手填 key 覆盖 |
| 档案 | 你/我 各八面的条数 + 二级记忆条数 |

## 隐私边界

- **它读什么**：`$DSH_HOME/sessions` 下的会话日志，按 `user/message`、`assistant/message`、
  `tool/call`、`tool/result` 等事件类型**逐条原样保留**。只读——不改你的上下文，也不动会话日志。
- **它存哪里**：`$DSH_ACC_HOME`，默认 `$DSH_HOME/acc/`。配置、档案、二级记忆以 `0600` 写入。
- **加不加锁**：`encrypt` 打开时，归档落盘前用 **AES-256-GCM** 封起来（密钥由口令经 scrypt 派生，
  口令文件 `0600`）；**关着就是明文**。备份写入即 `0444`，永不重写。
- **它发给谁**：记忆模型。默认借用 harness 已登录的那个，所以不需要第二把 key；
  归档内容会在你需要回忆时交给它，也就是会经过你现有的模型服务商。
- **图片**：不复制二进制，只留模型写的描述。

---

## 几条设计取舍

**1. 印象不是档案**
注入的是"你说话很简短"，不是完整原文。原文在归档里，需要时检索。

**2. 存储不截断**
tool 输出、assistant 文本都完整保留。压缩发生在注入层，不在存储层。

**3. 备份不可变**
一个能被改写的备份不能算证据。写入即 444，永不重写。

**4. 图片只留描述**
不复制二进制。模型看到图之后由它把内容写进 `images` 参数——
它看得到，记忆模型看不到。原图被清理后，剩下的就是"这张图讲了什么"。

**5. 回忆要用印象的口吻**
说"我对那张图的印象就这些"，不说"我没有原始文件了"。不隐瞒不确定，
但不把存储结构讲给用户听。

## 目录布局

```
<DSH_HOME>/acc/
├── config.json          root / encrypt / mode / resident
├── persona.json         八面（you / me）
├── deep.json            二级记忆
├── attachments.json     图片描述缓存
├── reports.jsonl        模型交上来的阶段汇报
├── conversations/       完整对话归档
└── backups/             日/周/月/年 + trash + README.txt
```
